== About

A login provider for OpenID Connect-enabled private sites.
It lets GitHub and GitLab organization members sign in to private resources when their org has installed the app.
It brokers GitHub and GitLab membership for private documentation sites.
The service is an OpenID Connect issuer a relying party can use.
GitHub organizations opt in by installing the GitHub App named Antora Private Docs Login.
GitLab groups opt in by inviting a configured user, because GitLab does not install apps the way GitHub does.
Cloudflare Access can be a client. It is not the required host.

== What this is for

The sign-in mechanism is general OpenID Connect: a relying party sends the reader to this issuer, and the token names the organizations or groups that opted in.
This distribution is for teams who publish private documentation (member-gated docs hubs, handbooks, and internal guides) and want to gate it on GitHub or GitLab organization membership.
It ships as its own product, with one install story, one GitHub App, and setup written for documentation sites, because that job is narrower than a generic identity provider.
The documentation language stays for that reason.
An Antora site behind Cloudflare Access, or another OpenID Connect relying party, is one common setup, not the only one, and this issuer does not gate arbitrary web applications.

== How login works

The login works like this:

. The private documentation site sends the reader to the issuer.
. The issuer sends the reader to GitHub, using the one published app.
. GitHub comes back to the issuer only.
. The issuer checks that the organization has installed the app and that this person is a member, then sends the reader back to the site.
. The site admits the reader only if the token names that organization.

One published app can gate many organizations' private documentation sites.
Each site asks for its own organization.
Members of one organization are not admitted to another organization's documentation.

The GitHub App has one callback, on the issuer.
Customer documentation URLs are not entered in the GitHub App settings.

A private documentation site is a relying-party client of the issuer.
The redirect URI is registered with the issuer.
That list is not the GitHub App.

An outside organization installs the published app.
That organization does not register a new GitHub App, and does not fork this repository, to use the hosted issuer.

== Run your own issuer

An organization cannot install the publisher's marketplace app and point it at an issuer they host.
GitHub only calls the callback URL registered on the app, which is the publisher's host.

Hosting an issuer means hosting a GitHub App for that issuer.

The reusable distribution is: the publisher runs the issuer, the organization installs the app, and the organization registers its documentation site as a client.

Run your own issuer when you do not want reader logins, membership checks, or client registration to pass through the publisher.
The reasons are trust, privacy, availability, data residency, or a policy that the identity provider must be yours.
Run your own when the GitHub callback has to be on your domain.
Run your own for GitHub Enterprise Server, where this marketplace app cannot be installed.
Run your own when you need to change claims, forges, or token rules yourself.
If the publisher's issuer is down, every private documentation site that depends on it cannot sign readers in.

You do not need your own issuer when you trust the publisher's issuer, and organization membership gating your own documentation site is enough.

== Start

Copy `config/issuer.example.sdl` to `config/issuer.sdl`.
Point `ANTORA_PRIVATE_DOCS_SIGNING_KEY_PATH` at a PKCS#8 PEM.
The other names are in link:docs/environment-variables.adoc[Environment variables].

[source,shell]
----
node bin/antora-private-docs.mjs serve --config config/issuer.sdl
----

This window shows the server.
The listen line prints the address.
Ctrl+C stops it.

Create the GitHub App (the browser approval is the remaining step):

[source,shell]
----
node bin/antora-private-docs.mjs github-manifest --config config/issuer.sdl
----

Print the GitLab application URL and fields:

[source,shell]
----
node bin/antora-private-docs.mjs gitlab-setup --config config/issuer.sdl
----

The task write-up is link:docs/how-to.adoc[How to run it] and, on the docs site, https://docs.antora-supplemental.org/home/how-to/private-docs-login/[Private docs login].
